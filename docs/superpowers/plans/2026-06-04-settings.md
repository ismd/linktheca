# Settings Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the `web/src/routes/settings.tsx` stub ("Coming soon") with a real read-only screen holding two section cards: **Account** (identity from `useAuthStore`) and **About** (version, mode, and Radar status from `useRadarStatusQuery`).

**Architecture:** Frontend only, with zero backend changes. A new light module, `features/settings/components/*` (with no api/schemas of its own — it consumes the existing `features/auth` store and the `features/radar` hook). The version moves into a shared `shared/version.ts` constant and is reused in the Sidebar (removing the duplicated hardcode). The `/settings` route is already registered in `App.tsx` — we only rewrite the body.

**Tech Stack:** TypeScript, React, React Router v7, TanStack Query v5, Tailwind (the project's editorial classes), Vitest + Testing Library + MSW.

**Existing facts the plan relies on (verified):**
- `PageHeader` (`@/shared/layout/PageHeader`): props `{ title: string; subtitle?: string; actions?: ReactNode }`; it renders `<h1 class="display-tight">{title}</h1>` plus `<p>{subtitle}</p>`.
- `User` (`@/features/auth/store`): `{ id: number; email: string; displayName: string; isAdmin: boolean }`. `useAuthStore` — zustand; `getState().setSession(token, user)` / `clearSession()`.
- `useRadarStatusQuery` (`@/features/radar/use-radar`): `useQuery` → `{ data?: { lastSweepAt: Date | null }, isLoading, isSuccess, error, ... }`.
- `fmtSweep` (`@/features/radar/time`): `(d: Date | null) => string` → `"Last sweep · <relative>"` or `"Awaiting first sweep"`.
- `ApiError` (`@/shared/api/errors`): the fields `status: number` and `code: string`. `apiFetch` throws `ApiError(res.status, code, …)`, where `code` comes from the `error` field of the `{ error, message }` JSON body (an OAuth2-style envelope, `internal/core/httpx`).
- `radar_disabled`: the backend returns it with HTTP `403` (`internal/radar/http.go`) — the feature is implemented but switched off by config, hence `403` rather than `501` "not implemented".
- MSW in tests: `server` from `@/test/setup`, `onUnhandledRequest: "error"` → every request must be mocked. `apiFetch` hits `/api/...`.
- The `/settings` route is already in `App.tsx:45` (`{ path: "settings", element: <SettingsRoute /> }`) — `App.tsx` does not need changing.
- Commands: a single test file is `npm test -- --run <path>`; the whole suite is `npm test`; lint is `npm run lint`; types are `npm run typecheck`; the build is `npm run build`. Run them from `web/`.

- [x] **Step 3: Implement `AboutSection.tsx`**

```tsx
import { ApiError } from "@/shared/api/errors";
import { useRadarStatusQuery } from "@/features/radar/use-radar";
import { fmtSweep } from "@/features/radar/time";
import { APP_VERSION } from "@/shared/version";
import { SettingRow } from "./SettingRow";

function radarStatusLabel(status: ReturnType<typeof useRadarStatusQuery>): string {
  if (status.isLoading) return "Checking…";
  if (status.isSuccess) return fmtSweep(status.data.lastSweepAt);
  if (status.error instanceof ApiError && status.error.code === "radar_disabled") {
    return "Disabled";
  }
  return "Unavailable";
}

export function AboutSection() {
  const status = useRadarStatusQuery();

  return (
    <section className="px-4 lg:px-8 py-8">
      <div className="mb-6">
        <h2 className="display-tight text-2xl text-ink mb-1">About</h2>
        <p className="font-body italic text-sm text-muted-foreground">
          This instance.
        </p>
      </div>
      <div className="bg-paper-2 border border-rule p-6 md:p-8 flex flex-col gap-4">
        <SettingRow label="Version" value={`v${APP_VERSION}`} />
        <SettingRow label="Mode" value="self-hosted" />
        <SettingRow label="Radar" value={radarStatusLabel(status)} />
      </div>
    </section>
  );
}
```
